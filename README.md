## 📋 Описание

Лабораторная работа по реализации взаимодействия сервисов на основе протокола XML-RPC с использованием Python. Система состоит из четырех компонентов:

1. **Основной сервер** (`xmlrpc_server.ipynb`) - обработка запросов
2. **Прокси-сервер** (`xmlrpc_proxy_server.ipynb`) - маршрутизация с Rate Limiting
3. **Сервер статистики** (`xmlrpc_stats2_server.ipynb`) - логирование в SQLite
4. **Клиент** (`xmlrpc_client.ipynb`) - интерфейс для тестирования

## 🎯 Реализованный функционал

### Основной сервер (порт 8008)
- ✅ Базовые функции: `ping`, `now`, `show_type`, `test_sum`, `test_pow`
- ✅ Проверка чёрного списка с нечувствительностью к регистру
- ✅ Алгоритм Левенштейна для поиска похожих имён (допуск 1 буква)
- ✅ Инверсия цвета изображения
- ✅ Бинаризация изображения по порогу
- ✅ Разворот изображения по вертикали
- ✅ Оценка процента облачности

### Прокси-сервер (порт 8010)
- ✅ Маршрутизация запросов от клиента к основному серверу
- ✅ **Rate Limiting**: 5 запросов в 5 секунд
- ✅ Регистрация событий с временем и длительностью
- ✅ Логирование события `too_many_requests` при превышении лимита
- ✅ Передача статистики на сервер логирования

### Сервер статистики (порт 8009)
- ✅ Сохранение событий в SQLite БД (`log.db`)
- ✅ Таблица: `id`, `event_time`, `event_type`, `duration`
- ✅ Фильтрация по типу события, времени, длительности
- ✅ Вычисление общей статистики (count, avg, min, max)
- ✅ Отказоустойчивость: основной сервер работает без stats

### Клиент
- ✅ Тестирование всех функций сервера
- ✅ Визуализация результатов обработки изображений
- ✅ Проверка Rate Limiting
- ✅ Получение и фильтрация журнала событий
- ✅ Отображение общей статистики

import pickle
from PIL import Image
import xmlrpc.client

img = Image.open('Jellyfish.jpg')
img_arr = np.array(img)

# Инверсия
result = server.color_inversion(bin_data)
inverted = pickle.loads(result.data)

# Бинаризация
result = server.binarize_image(bin_data, threshold=128)

## 📌 Выводы

Взаимодействие сервисов позволяет:
- **Разделить ответственность**: каждый сервис решает одну задачу
- **Упростить масштабирование**: можно запускать несколько экземпляров
- **Повысить отказоустойчивость**: при падении статистики основной функционал работает
- **Контролировать нагрузку**: Rate Limiting защищает от перегрузки
